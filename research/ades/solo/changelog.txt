Start at Compare . v0.12.4 Released on October 31, 2026 TL;DR Stopping a command now lets it shut down cleanly. On macOS and Linux, Solo asks it to exit the way Ctrl+C would and escalates only if it keeps running. On Windows, Solo sends Ctrl+C and force-stops only after about 3 seconds. Child processes are stopped too, and a project whose folder is missing at startup is kept instead of removed. Timer and MCP messages to agents are much more dependable. They no longer get stuck unsubmitted in a prompt, never answer a permission prompt or question for you, and typing into an agent mid-delivery no longer locks its terminal. Resume also follows Claude Code's /clear and /resume , and Codex's -C . MCP gives you control over who can type into a process. Each process has an "Incoming MCP input" setting and keeps a log of the input it received, and agents can tell MCP input from your typing. spawn_agent also takes a working directory and a first prompt. A project's name now stays in sync with its solo.yml , and adding a git worktree of a project you already have links it to that project instead of creating a new one. Shortcuts changed: Cmd/Ctrl+1–9 switch between sessions across the whole workspace. On new installs, Focus sidebar and Focus terminal use Cmd+Shift+Left/Right on macOS and Ctrl+Shift+Left/Right on Windows, so they work from inside a terminal. If you're updating, they stay on Cmd+Left/Right (Ctrl+Left/Right on Windows) until you change them. Windows and WSL got a lot of fixes: Ctrl+C copies selected terminal text, Windows Terminal is easy to set up and opens in the right folder, and WSL agents and commands get the PATH from your shell setup. Added Processes & Projects A project's name now stays in sync with its solo.yml . Editing name: in solo.yml renames the project in Solo, and renaming a project in Solo (including through MCP rename_project ) rewrites only the name: line, keeping comments, other keys, and line endings. Clearing the name removes the name: line, and a solo.yml without name: leaves the name you set in Solo alone. Renaming is refused while solo.yml has changes Solo hasn't synced yet, or when its name uses a quoted key or spans several lines, and Solo says why. Worktree projects are the exception: a linked worktree is named after the name you give it or its folder, syncing ignores its solo.yml name: , and renaming it changes only Solo's name for it, never its solo.yml . Adding a folder that is a git worktree of a project already in Solo now links it to that project as a worktree and places it in the project's workspace, instead of creating a separate, unrelated project. Reopening a worktree that was added as a standalone project before Solo detected worktrees also links it, as long as the old project holds no commands or other data. MCP spawn_agent accepts an optional working_dir , such as a sibling git worktree, and an optional prompt that is sent as the agent's first message once it starts. The response reports whether the prompt was delivered. Each process has a new "Incoming MCP input" setting in its process settings: Allow all MCP callers (the default, so nothing changes until you pick another), Same project or spawning process, This process or spawning process, or Block all MCP input. It controls send_input , first prompts from spawn_agent , and timers aimed at the process from another process; your own typing is never affected.
