Cubebot is a self-hosted runtime for persistent AI agents. Each one gets its own sandbox, its own volume, one permanent conversation, and a memory that outlives any restart. Built in Rust, in the open, on infrastructure you control. Star on GitHub Read the architecture curl -fsSL https://cubebot.io/install.sh | bash z z z An agent is something you can hold. Most agent tools give you a chat window and a process that disappears when it closes. Cubebot gives each agent a durable body. Stack the pieces and you have something that keeps its identity through restarts, upgrades, and replaced hardware. Hover a piece to find it in the stack. sandbox volume journal chat memory skills sandbox Its own sandbox A running agent is one sandbox: a KVM guest of its own, or a declared container where KVM is not available. Its tools run inside it, and it stays on, ready for work. volume A workspace that stays Files live on a persistent volume. Stop, upgrade, or replace the sandbox; the workspace is still there. journal A recovery journal Every intent and outcome is written to a private journal before it happens. A crash never replays a tool call blindly. chat One permanent conversation Exactly one continuous history per agent. No sessions to lose and nothing to re-explain after a restart. memory One memory, everywhere A single memory pool across every room and task. Idle agents dream: consolidating, reconciling, and summarizing what they learned. skills Skills it can grow Reusable procedures from a shared library, with revisions and provenance, installed per agent and never a source of extra permissions. Give it work, not a prompt. An agent has a computer of its own, your accounts within the permissions you set, and a console where you can watch every step. Here is some of what that adds up to today.
